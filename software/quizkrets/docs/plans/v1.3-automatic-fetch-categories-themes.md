## 4. Detaljerte kravsporing

- [ ] Endre `writeBank()` til å kaste `StorageError` i stedet for `slice(-MAX_QUESTIONS)`

- [ ] Feilmelding: "Spørsmålsbanken er full (X av 5000 spørsmål). Nye spørsmål kan ikke legges til. Eksporter banken som backup."
- [ ] `verifyPersisted()` må sjekke hele forventet datasett
- [ ] Test: import ved 4 999, 5 000 og 5 001 spørsmål
- [ ] Test: migrering ved full bank bevarer alle eksisterende spørsmål

**A2. Unike ID-er (P0)**
- [ ] `addQuestions()`: Sjekk ID-kollisjon eksplisitt

- [ ] Ved duplikat-ID med annen tekst → generer ny unik ID (f.eks. legg til hash-counter)
- [ ] Håndter kollisjoner innen samme batch og under migrering
- [ ] Bevar kildeinformasjon uten å ødelegge quizhistorikk
- [ ] Test: ID-kollisjon med identisk tekst, annen tekst, innen batch, migrering

**A3. Rett CSV-import**
- [ ] `csvToDrafts()`: Ikke filtrer bort tomme choice-felter – behold posisjon
- [ ] Fasit må peke på et ikke-tomt alternativ
- [ ] Avvis rad hvis fasit peker på tomt felt
- [ ] Test: `choice_a = Oslo, choice_b = tomt, choice_c = Bergen, correct = b` → avvist
- [ ] Test: tomme felt, manglende kolonner, ugyldige fasitbokstaver, duplikater, spesialtegn, siterte felt

**A4. Valider lagoppsett**
- [ ] `buildTeams()`: Returner valideringsfeil i stedet for å bygge ugyldige lag

**A5. Tydelig lagring og importbekreftelse**

**A6. Beskytt mot korrupte lagringsdata**

### DEL B – Automatisk innhenting

## 5. Risikoanalyse

| Risiko | Sannsynlighet | Konsekvens | Tiltak |
|--------|---------------|------------|--------|
| API-endringer (The Trivia API) | Medium | AutoFetch feiler | Graceful fallback, cachen logger siste kjente struktur |
| Rate-limiting ved mange brukere | Medium | Treghet | Eksponentiell backoff, delt cache |
| localStorage-kvote nærmer seg | Høy | Ingen nye spørsmål | Tydelig varsel, eksport-anbefaling uten auto-sletting |
| Korrupt data fra eldre versjoner | Lav | Tom spørsmålsbank | Backup-funksjon, feilhåndtering som bevarer data |

## 6. Nøkkelbeslutninger logget

1. **Ikke øk MAX_QUESTIONS** – grensen på 5000 er en sikkerhetsmekanisme, ikke en løsning.
2. **Ikke generer spørsmål med AI** – kun dokumenterte eksterne kilder.
3. **Ikke lag API-nøkler i klientkode** – kun gratis endepunkter uten nøkkel.
4. **Bakoverkompatibel datamodell** – gamle spørsmål uten `providerTags` skal fungere.
5. **Automatisk henting er opt-out** – bruker ser tydelig hva som hentes og kan avbryte.
